# GitHub Pages Deployment Fix

The GitHub Actions workflow has been updated to use the official GitHub Pages deployment action. However, you need to configure your repository's GitHub Pages settings.

## Step-by-Step Setup

### 1. Enable GitHub Pages in Your Repository

1. Go to your GitHub repository: `https://github.com/bramvankooten/mijnenveger`
2. Click **Settings** (top right)
3. In the left sidebar, scroll down and click **Pages**
4. Under "Build and deployment":
   - **Source**: Select "GitHub Actions"
   - This is the key setting that was likely causing the permission error

### 2. Verify Workflow Permissions

The workflow now includes the proper permissions:
```yaml
permissions:
  contents: read
  pages: write
  id-token: write
```

These permissions allow the GitHub Actions bot to:
- Read your repository contents
- Write to GitHub Pages
- Request deployment tokens

### 3. Configure GitHub Pages for Deployment

If you see branch options (old GitHub Pages settings):
- Make sure there's **no custom branch** set for GitHub Pages deployment
- The workflow should be the only deployment method
- Delete any old deployment branches if they exist

### 4. Test the Workflow

1. Make any small change to your `main` branch
2. Commit and push: `git add . && git commit -m "test" && git push`
3. Go to your repository's **Actions** tab
4. Watch the "Build and Deploy" workflow run
5. Check the workflow logs for any errors

### 5. Verify Deployment

Once successful:
- Your site will be available at: `https://bramvankooten.github.io/mijnenveger/`
- The deployment URL will be shown in the workflow summary

## Troubleshooting

### Still Getting Permission Errors?

1. **Check repository visibility**:
   - Go to Settings → General
   - Scroll to "Danger Zone"
   - Verify the repository name and owner are correct

2. **Check GitHub Pages settings**:
   - Go to Settings → Pages
   - Confirm "Source" is set to "GitHub Actions"
   - NOT a specific branch

3. **Check workflow permissions**:
   - Go to Settings → Actions → General
   - Under "Workflow permissions", select:
     - ☑ Read and write permissions
     - ☑ Allow GitHub Actions to create and approve pull requests

4. **Clear stale deployments**:
   - Go to Settings → Pages
   - Look for any old deployment branches
   - If there's a dropdown for branches, make sure it's not set to a specific branch

### Workflow Still Failing?

Check the full error in Actions:
1. Go to **Actions** tab
2. Click the failed workflow run
3. Click **Build and Deploy** job
4. Expand the failed step to see full error message
5. Common issues:
   - Missing GitHub Pages source configuration
   - Insufficient workflow permissions
   - Secret names not matching (`SUPABASE_URL`, `SUPABASE_ANON_KEY`)

### Site Not Appearing After Successful Build?

1. Wait 2-5 minutes for GitHub Pages to publish
2. Check that your site is public:
   - Settings → Pages → "Pages is currently disabled"?
   - If so, GitHub Pages publishing failed
3. Clear browser cache and try again
4. Check the correct URL: `https://bramvankooten.github.io/mijnenveger/`

## File Paths for GitHub Pages

Make sure all file references in your HTML are correct:

```html
<!-- Use relative paths -->
<link rel="stylesheet" href="style.css">
<script src="script.js"></script>

<!-- NOT absolute paths -->
<link rel="stylesheet" href="/style.css">
```

Your directory structure should look like:
```
/
├── index.html
├── style.css
├── script.js
├── config.js (generated by workflow)
└── ... other files
```
